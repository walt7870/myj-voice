## 2026-08-04 设备实体按键打断播报

- 设备 WebSocket 新增独立控制事件 `tts_interrupt`。请求必须携带当前连接已经收到的 `conversation_id + turn_id`，本期 `source` 固定为 `button`；服务端以 `tts_interrupted` 返回 `interrupted`、`already_interrupted` 或 `already_finished`，非法字段、来源、未知轮次或跨会话轮次返回 `bad_request`。
- 本地优先停播：Python/C++ SDK 的 `interrupt_tts_from_button` 先停止播放器并清空预缓冲、乱序 seq 和待播队列，再发送控制帧。发送失败不会恢复旧音频；重复按钮或没有活跃播报时为 no-op。
- SDK 按 `conversation_id + turn_id` 保存最多 64 个近期被打断轮次，相同 pair 的迟到 `llm_delta`、`reply_sentence`、`tts_audio_chunk`、`voice_done` 在 base64 解码和 seq 校验前丢弃，新轮次仍可正常播放。
- 被打断轮不再发送普通 `voice_done`，以 `tts_interrupted` 作为播放终止确认；设备本地恢复拾音不依赖确认，也不增加固定 500ms 延时。命令行单轮 demo 会继续读取到 `latency_metrics` 业务尾，常驻设备则保持原 WebSocket 并可立即开始下一轮 ASR。
- 服务端取消范围只覆盖旧轮的 LLM/reply/TTS producer，provider 等待任务会主动终止并释放完整轮次容量；已经启动的商品分析、订单草稿、下单、退款等业务动作不取消，同一 conversation 的分析/写动作仍按轮次顺序提交。
- 本地自动化已覆盖合法/重复/完成/非法打断、最后一个 TTS 包与确认并发、业务事件保留、同连接下一轮、provider 中途取消、SDK 本地停播与迟到过滤、播放器进程组有界回收等契约。Python 提供 `protocol_self_test.py`，C++ 提供 `--self-test` 和 `--interrupt-after-first-chunk`。

## 已完成内容

### 1. 语音购物服务

- 后端使用 Rust `axum + tokio + sqlite + tokio-tungstenite`。
- 前端由后端托管，包含体验页和管理后台。
- 支持讯飞中英听写、大模型推理、超拟人合成、在线语音合成兜底。
- 支持模型选择：`xopdeepseekv4pro`、`xopdeepseekv4flash`、`xopdsv32exp`，默认 `xopdeepseekv4flash`。
- 支持超拟人发音人配置，当前保留 `聆小璇 / x6_lingxiaoxuan_pro` 和 `聆飞瀚 / x6_lingfeihan_pro`。

### 2. 体验页交互

- 体验页按三栏布局：左侧体验配置，中间语音交互，右侧下单意向和链路诊断。
- 页面不保留下单按钮，订单动作由语音控制。
- 一问一答作为一条 turn 数据记录，一轮 conversation 支持多次问答。
- 支持“新一轮”开启新的 conversation。
- 用户文本发送后清空输入框。
- 识别到结束对话意图后下发 `conversation_ended`，前端关闭麦克风监听。

### 3. 低延迟与流式链路

- 浏览器和设备协议支持 `audio_stream_start/chunk/end`。
- 服务端收到音频 chunk 后立即转发讯飞 IAT。
- ASR partial 只做展示和诊断，LLM 与订单判断等待 ASR final。
- 每个 IAT 分段只采用首选候选，候选列表不得串接为重复用户文本。
- 大模型流式输出后，超拟人模式下继续作为 TTS 流式文本输入。
- TTS 返回 `tts_audio_chunk`，前端使用 MediaSource 边收边播。
- 当前低延迟参数：
  - `silenceMs = 320`，可调 `250-400ms`
  - `minSpeechMs = 350`，可调 `300-500ms`
  - `preSpeechMs = 250`，可调 `200-300ms`
  - `maxSpeechMs = 10000ms`
  - `STREAMING_TTS_PREBUFFER_BYTES = 4096`
- `maxSpeechMs` 同时由独立定时器执行硬截止，不依赖后续音频处理回调。

### 4. 播报拾音门控

- TTS 首个音频分片进入待播放链路后立即关闭拾音，播报期间不发送普通 ASR 或打断检测音频。
- 门控开始时清空当前录音窗口，状态区和麦克风按钮统一显示“播报中，暂停收音”。
- `voice_done`、空 ASR 等异步事件不能在播报未结束时把页面改回“持续监听中”。
- 最后一段播放触发浏览器 `ended` 后立即恢复持续监听并同步更新页面状态，不再叠加固定 500ms 等待。

### 5. 订单链路

- 体验页右侧展示商品命中、待下发订单、已下发订单、已退订单和链路诊断。
- 用户表达购买意图后，服务端先播报确认内容。
- 用户确认下单后调用订单接入层。
- 退单只接受“我要退单/退款”“帮我取消订单”等完整、明确请求；裸词、模糊表达、否定表达和“退下/推下”均不得触发。
- 当前订单写操作支持客户 MCP 文档约定的 JSON-RPC + SSE 响应；未启用 MCP 时走本地 mock 仅用于开发验证，真实 MCP 启用后失败不再生成假订单。
- 客户固定接口地址、门店和会员上下文集中在 `src/config.rs`，请求自动补齐文档要求的通用 Header；正式值由客户提供后替换配置即可。
- 订单 MCP 页面支持配置 Server URL、Token、上下文 JSON 和内部能力到客户工具名映射。

### 6. 设备接入和 SDK

- 设备接口：
  - `GET /api/device/config`
  - `POST /api/device/auth`
  - `WS /api/device/voice`
  - `POST /api/device/status`
- 本机调试演示设备：`DOLL-0001 / demo-secret`，仅 loopback/SSH 隧道可用；公网设备必须线下配置独立凭据。
- SDK 路径：`SDKs/`。
- Python SDK 支持公网 HTTPS/WSS，主上下文路径为 `/myj-voice-shop`，并兼容旧 `/mjy-voice-shop`。
- C++ SDK 当前支持本地或内网明文 HTTP/WS；直接上公网需要接 TLS/WebSocket 库或网关反代。
- 设备主要职责：拾音、VAD 断句、上传连接指定格式音频、接收指定格式 TTS chunk 并实时播报。
- 本地服务与 Python/C++ SDK 已具备 `tts_interrupt`/`tts_interrupted` 按键打断契约；SDK 先本地停播，再通知服务端，保持同一 WebSocket 继续下一轮。真实 GPIO/decoder/DAC HAL 尚不在本仓库。

### 7. 部署

- 远程目标：`root@jd`。
- 远程服务目录：`/opt/mjy-voice-shop-rs`。
- 远程源码目录：`/opt/mjy-voice-shop-rs-src`。
- systemd：`mjy-voice-shop-rs.service`。
- 部署脚本：`scripts/deploy-jd.sh`。

## 当前边界

- 设备到服务端使用 JSON + base64 的 MP3/PCM/已启用原生压缩包；具体档位以动态能力为准，后续可评估 WebSocket binary frame。
- 讯飞 IAT 本身要求音频在 JSON 字段中 base64，因此服务端到讯飞仍需 base64。
- ASR final 之前不触发 LLM 下单理解，避免用户没说完时误判。
- 客户最新文档已补齐会员授权、门店、商品搜索/详情/属性、订单预览、创建和订单详情；支付、退款、取消、订单列表仍待最终 MCP 工具契约。
- 体验页是验证入口，最终设备侧以嵌入式接入为主。
