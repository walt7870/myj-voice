# 美宜佳语音购物服务端部署说明

本文是 `mjy-voice-shop-rs` 的部署操作手册，覆盖首次部署、日常发布、Nginx/systemd 配置、发布后验收、回滚和凭据轮换。

## 1. 部署拓扑与固定路径

| 项目 | 当前约定 |
| --- | --- |
| SSH 目标 | `root@jd`（也可通过 `REMOTE` 覆盖） |
| 远程运行目录 | `/opt/mjy-voice-shop-rs` |
| 远程源码/构建目录 | `/opt/mjy-voice-shop-rs-src` |
| systemd 单元 | `mjy-voice-shop-rs.service` |
| 内部监听 | `0.0.0.0:8787` |
| 主公网路径 | `https://www.niuwancheng.cn/myj-voice-shop/` |
| 兼容旧路径 | `https://www.niuwancheng.cn/mjy-voice-shop/` |
| 发布脚本 | `scripts/deploy-jd.sh` |

服务本身只监听 HTTP/WebSocket，公网 TLS 和路径前缀由 Nginx 终止和转发。Nginx 配置片段位于 `deploy/mjy-voice-shop-nginx.locations.conf`，必须放在对应的 HTTPS `server {}` 中。

## 2. 发布前准备

### 2.1 本地检查

```bash
cd /Users/niu/Documents/公司/项目/美宜佳/新玩偶需求/mjy-voice-shop-rs

# shell 语法和 Rust 测试
bash -n scripts/deploy-jd.sh
cargo fmt --all -- --check
cargo test
```

如果需要跑浏览器/音频门禁，先按本地开发说明启动服务，再执行：

```bash
npm run voice:check
npm run audio:check
```

### 2.2 SSH 和远端检查

```bash
ssh jd 'hostname; id; command -v systemctl; command -v curl'
ssh jd 'test -d /opt || true'
```

发布脚本会在远端检查 Rust；缺少或版本低于 `1.85.0` 时，会通过 rsproxy 安装 stable toolchain，并配置 Cargo 镜像。远端还需要 `tar`、`curl`、`python3` 和 systemd。

### 2.3 生产配置准备

生产 `.env` 不从 Git 上传，也不要把真实凭据写入命令行或日志。至少确认以下变量：

```dotenv
HOST=0.0.0.0
PORT=8787
DATABASE_URL=sqlite:///opt/mjy-voice-shop-rs/mjy_voice_shop.db
MOCK_PROVIDERS=0
XF_APP_ID=<讯飞应用 ID>
XF_API_KEY=<讯飞 API Key>
XF_API_SECRET=<讯飞 API Secret>
SERVER_SECRET=<随机生成的长字符串>
ADMIN_USERNAME=myjadmin
ADMIN_PASSWORD_HASH=<Argon2id 哈希>
```

如启用订单 MCP，再配置 `MJY_ORDER_MCP_ENABLED=1`、`MJY_ORDER_MCP_URL`、`MCP_HTTP_TOKEN` 及对应的订单上下文；未启用时服务使用本地 mock/fallback，不能当作生产订单链路。

首次部署可以让脚本从 `.env.example` 创建 `.env`，但这只适合测试环境。生产环境必须在服务启动前替换所有占位值，尤其是 `MOCK_PROVIDERS`、讯飞凭据和 `SERVER_SECRET`。

管理员密码哈希生成方式：

```bash
printf '%s' '请替换为管理员密码' \
  | cargo run --bin mjy-admin-password -- hash
```

将输出写入远端 `.env` 的 `ADMIN_PASSWORD_HASH`，文件权限保持 `0600`。

## 3. 日常发布

### 3.1 推荐命令

```bash
cd /Users/niu/Documents/公司/项目/美宜佳/新玩偶需求/mjy-voice-shop-rs
REMOTE=root@jd ROTATE_ADMIN_CREDENTIALS=0 bash scripts/deploy-jd.sh
```

常用变量：

```bash
REMOTE=root@jd \
APP_DIR=/opt/mjy-voice-shop-rs \
SRC_DIR=/opt/mjy-voice-shop-rs-src \
SERVICE_NAME=mjy-voice-shop-rs.service \
ROTATE_ADMIN_CREDENTIALS=0 \
bash scripts/deploy-jd.sh
```

### 3.2 脚本执行内容

脚本会按以下顺序执行：

1. 将当前源码打包，排除 `target/`、`node_modules/`、日志、运行状态、UI 报告、SQLite 数据库、`.env` 和 macOS 元数据。
2. 通过 SCP 上传到远端 `/tmp/mjy-voice-shop-rs-source.tar.gz`。
3. 在远端源码目录构建 release 二进制。
4. 停止当前服务，备份旧二进制、管理密码工具、静态资源、`.env` 和 SQLite 数据库。
5. 停用已知旧 MCP systemd 服务，并将旧 MCP 目录改名为带时间戳的 `.disabled-*` 目录，不直接删除。
6. 安装新二进制和静态资源，安装 systemd 单元，执行 `daemon-reload`，设置开机启动并启动服务。
7. 访问远端本机 `/api/health`；成功后打印备份目录。

发布结束时请记录脚本输出中的：

```text
RELEASE_BACKUP=/opt/mjy-voice-shop-rs-backups/<timestamp>
```

如果脚本因为没有有效 `ADMIN_PASSWORD_HASH` 而自动生成管理员密码，还会打印一次 `INITIAL_ADMIN_PASSWORD`。必须通过安全渠道保存并在交接后修改，不能复制到工单、群聊或日志。

## 4. systemd 配置

模板文件：`deploy/mjy-voice-shop-rs.service`。

安装或手工更新：

```bash
sudo install -m 0644 deploy/mjy-voice-shop-rs.service \
  /etc/systemd/system/mjy-voice-shop-rs.service
sudo systemctl daemon-reload
sudo systemctl enable --now mjy-voice-shop-rs.service
```

常用运维命令：

```bash
sudo systemctl is-active mjy-voice-shop-rs.service
sudo systemctl status mjy-voice-shop-rs.service --no-pager --full
sudo systemctl restart mjy-voice-shop-rs.service
sudo journalctl -u mjy-voice-shop-rs.service -n 100 --no-pager
sudo journalctl -u mjy-voice-shop-rs.service -f
```

当前模板从 `/opt/mjy-voice-shop-rs/.env` 读取配置，工作目录也是该目录；数据库使用绝对路径时可避免手工启动目录不一致。修改 `.env` 后必须重启服务。

## 5. Nginx 配置

将 `deploy/mjy-voice-shop-nginx.locations.conf` 的两个 location 组放入 HTTPS `server {}`：

- `/myj-voice-shop/`：主路径；
- `/mjy-voice-shop/`：旧设备和历史链接兼容路径。

配置检查和加载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

配置必须保留以下能力：

- `proxy_http_version 1.1`、`Upgrade`、`Connection`，否则 WebSocket 无法升级；
- `proxy_buffering off`，避免流式 TTS 被缓冲；
- `proxy_read_timeout` 和 `proxy_send_timeout` 足够覆盖长语音会话；
- TLS 证书、域名和防火墙规则由服务器基础设施维护，不由 Rust 发布脚本修改。

## 6. 发布后验收

### 6.1 远端本机验收

```bash
ssh jd 'systemctl is-active mjy-voice-shop-rs.service'
ssh jd 'curl -fsS http://127.0.0.1:8787/api/health'
ssh jd 'curl -fsS http://127.0.0.1:8787/api/device/config'
```

健康检查预期返回：

```json
{"status":"ok","service":"mjy-voice-shop-rs"}
```

### 6.2 公网验收

```bash
curl -fsS https://www.niuwancheng.cn/myj-voice-shop/api/health
curl -fsS https://www.niuwancheng.cn/myj-voice-shop/api/device/config

cd /Users/niu/Documents/公司/项目/美宜佳/新玩偶需求/mjy-voice-shop-rs
BASE_URL=https://www.niuwancheng.cn/myj-voice-shop npm run cloud:smoke
```

公网 smoke 会检查健康接口、匿名管理接口必须拒绝、演示设备凭据必须拒绝、默认音频档位和浏览器 Chat WebSocket 语音链路。验收失败时先查看 Nginx error log 和 systemd journal，再判断是路由、服务、凭据还是外部 provider 问题。

### 6.3 设备链路验收顺序

1. `GET /api/device/config`，读取当前输入/输出 profile。
2. 使用已配置的一机一密调用 `POST /api/device/auth`。
3. 按返回的四个音频参数建立 `/api/device/voice` WebSocket。
4. 发送 `audio_stream_start/chunk/end`，确认收到 `tts_audio_chunk` 和 `voice_done`。
5. 验证按键打断、下一轮语音和订单事件没有串轮。

公网禁止使用 `DOLL-0001/demo-secret`；该凭据只用于回环或本地开发测试。

## 7. 回滚

### 7.1 脚本自动回滚范围

发布过程中发生错误时，脚本会尝试停止服务并恢复备份目录中的：

- `mjy-voice-shop-rs` 二进制；
- `mjy-admin-password`；
- `static/`；
- `.env`。

SQLite 备份只会被保存并执行 `PRAGMA quick_check`，不会在失败时自动覆盖当前数据库。数据库恢复必须由负责人确认，避免把新版本已写入的数据回退掉。

### 7.2 手工回滚二进制和静态资源

将 `<timestamp>` 替换为本次发布输出的目录：

```bash
BACKUP=/opt/mjy-voice-shop-rs-backups/<timestamp>
APP=/opt/mjy-voice-shop-rs

ssh jd "sudo systemctl stop mjy-voice-shop-rs.service && \
  sudo install -m 0755 '${BACKUP}/mjy-voice-shop-rs' '${APP}/mjy-voice-shop-rs' && \
  sudo install -m 0755 '${BACKUP}/mjy-admin-password' '${APP}/mjy-admin-password' && \
  sudo rm -rf '${APP}/static' && sudo cp -a '${BACKUP}/static' '${APP}/static' && \
  sudo install -m 0600 '${BACKUP}/.env' '${APP}/.env' && \
  sudo systemctl start mjy-voice-shop-rs.service"
```

回滚后重新执行第 6 节验收，并记录回滚原因和备份目录。不要执行 `rm -rf` 指向未确认的路径；数据库恢复前先停止服务并制作当前数据库副本。

## 8. 管理员凭据轮换

日常发布不要轮换管理员凭据：

```bash
ROTATE_ADMIN_CREDENTIALS=0 bash scripts/deploy-jd.sh
```

明确需要轮换时才执行：

```bash
ROTATE_ADMIN_CREDENTIALS=1 bash scripts/deploy-jd.sh
```

脚本会备份旧 `.env`，生成新的随机管理员初始密码并在终端打印一次。发布人员必须使用安全渠道交付，登录后立即修改。轮换完成后检查管理员登录、设备授权页面和服务日志。

## 9. 常见故障

| 现象 | 检查方向 |
| --- | --- |
| `ssh jd` 失败 | SSH alias、密钥权限、远端网络和 root/sudo 权限 |
| Cargo 下载失败 | 远端 Cargo rsproxy 配置、DNS/网络和磁盘空间 |
| systemd 启动失败 | `journalctl -u ...`；重点检查 `.env`、数据库路径、端口占用和权限 |
| Nginx 502 | 服务是否监听 `127.0.0.1:8787`/`0.0.0.0:8787`、端口和反代地址是否一致 |
| 页面能开但 WebSocket 失败 | Nginx `Upgrade/Connection`、HTTPS/WSS、超时和路径前缀 |
| 公网 smoke 拒绝 | 这是预期门禁时检查状态码；若健康接口也失败，再查服务和 Nginx |
| 设备鉴权失败 | 设备 ID/密钥是否为已授权的一机一密，时间是否准确，是否误用演示凭据 |
