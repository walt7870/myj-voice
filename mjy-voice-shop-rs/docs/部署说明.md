# 美宜佳语音购物服务端：新服务器从零部署

本文只描述“拿到一台干净 Linux 服务器后如何部署”，不包含任何现有机器、内网、域名、账号、目录或历史发布记录。

文中的尖括号变量必须替换为本次部署自己的值；不要把真实密码、API Secret、token 或私钥写入 Git、命令历史或工单。

## 1. 先确定本次部署变量

在执行命令前，先准备以下变量：

| 变量 | 示例含义 |
| --- | --- |
| `<SSH_TARGET>` | `deploy@server.example.com`，可使用 IP |
| `<APP_DIR>` | 远端运行目录，例如 `/srv/mjy-voice-shop-rs`；必须是无空格绝对路径 |
| `<SRC_DIR>` | 远端源码和构建目录，例如 `/srv/mjy-voice-shop-rs-src`；必须是无空格绝对路径 |
| `<PUBLIC_BASE_URL>` | 对外 HTTPS 地址，例如 `https://voice.example.com/voice-shop` |
| `<SERVICE_NAME>` | 默认 `mjy-voice-shop-rs.service` |
| `<BASE_PATH>` | Nginx 反向代理前缀；使用根路径时为空 |

发布脚本要求显式传入 `<SSH_TARGET>`、`<APP_DIR>`、`<SRC_DIR>`，不会使用任何预置服务器地址或目录。

## 2. 新服务器基础环境

以下以 Debian/Ubuntu x86_64 为例；其他发行版安装同名软件包即可。脚本会自动安装 Rust stable，但不会替代系统基础包安装。

当前脚本中的 rustup 下载地址按 x86_64 Linux 处理；ARM 或其他架构请先在服务器手工安装对应 Rust toolchain，再执行发布脚本。

```bash
sudo apt-get update
sudo apt-get install -y \
  ca-certificates curl openssh-server tar python3 \
  build-essential pkg-config libssl-dev sqlite3 nginx
```

确认：

```bash
sudo systemctl enable --now ssh
sudo systemctl is-active ssh
uname -m
```

建议同时完成：

- 配置时区和 NTP 时间同步；设备 token、TLS 和日志时间都依赖正确时钟。
- 创建专用部署账号并配置 SSH 公钥；账号需要使用 `sudo` 安装 systemd/Nginx 和写入运行目录。
- 仅开放 SSH、HTTP（用于证书签发，如需要）和 HTTPS；应用端口只允许本机或 Nginx 访问。
- 确保服务器有足够磁盘空间用于 Cargo 编译缓存、发布备份和 SQLite 数据库。

登录验证：

```bash
ssh <SSH_TARGET> 'id; command -v sudo; command -v systemctl; command -v curl; command -v tar'
```

## 3. 获取代码与发布前检查

在发布机上操作，不要把本地绝对路径写入文档或配置：

```bash
git clone <REPOSITORY_URL> <CHECKOUT_DIR>
cd <CHECKOUT_DIR>/mjy-voice-shop-rs

bash -n scripts/deploy-jd.sh
cargo fmt --all -- --check
cargo test
```

如果需要跑浏览器或音频门禁，先准备 Node.js 依赖，再按项目现有本地开发方式启动服务：

```bash
npm install
npm run voice:check
npm run audio:check
```

发布前确认 Git 工作区干净，且没有被强制加入的 `.env`、数据库、日志、`target/` 或 `node_modules/`。

## 4. 准备生产配置

### 4.1 必填配置

推荐在远端通过密码管理器、云厂商 Secret 或受控文件传输创建 `${APP_DIR}/.env`，权限设为 `0600`。下面仅是字段模板：

```dotenv
HOST=0.0.0.0
PORT=8787
DATABASE_URL=sqlite:///absolute/path/to/mjy_voice_shop.db
MOCK_PROVIDERS=0
XF_APP_ID=<讯飞应用 ID>
XF_API_KEY=<讯飞 API Key>
XF_API_SECRET=<讯飞 API Secret>
SERVER_SECRET=<随机生成的长字符串>
ADMIN_USERNAME=<管理员用户名>
ADMIN_PASSWORD_HASH=<Argon2id 密码哈希>
```

生产环境不能保留 `.env.example` 中的占位值，尤其是：

- `MOCK_PROVIDERS` 必须关闭；
- `XF_APP_ID`、`XF_API_KEY`、`XF_API_SECRET` 必须是当前环境凭据；
- `SERVER_SECRET` 必须是独立、随机、足够长的服务端签名密钥；
- `ADMIN_PASSWORD_HASH` 必须是 Argon2id 哈希，不能写明文密码。

管理员密码哈希在有 Rust 工具链的发布机生成：

```bash
printf '%s' '<管理员密码>' \
  | cargo run --bin mjy-admin-password -- hash
```

### 4.2 可选配置

启用真实订单 MCP 时，再配置：

```dotenv
MJY_ORDER_MCP_ENABLED=1
MJY_ORDER_MCP_URL=<订单 MCP 地址>
MCP_HTTP_TOKEN=<MCP 访问 token>
```

同时确认订单上下文和工具名与实际 MCP 契约一致。未启用 MCP 时，服务可以使用 mock/fallback 做开发验证，但不能把该模式当作生产订单链路。

### 4.3 首次无 `.env` 的情况

如果远端没有 `${APP_DIR}/.env`，发布脚本会复制 `.env.example` 并生成管理员初始密码。这只适合先让服务启动起来做测试；脚本结束后必须立即补齐真实 provider、`SERVER_SECRET` 和订单配置，然后重启服务。

## 5. 首次发布

### 5.1 执行发布脚本

```bash
cd <CHECKOUT_DIR>/mjy-voice-shop-rs

REMOTE=<SSH_TARGET> \
APP_DIR=<APP_DIR> \
SRC_DIR=<SRC_DIR> \
SERVICE_NAME=mjy-voice-shop-rs.service \
ROTATE_ADMIN_CREDENTIALS=0 \
bash scripts/deploy-jd.sh
```

脚本会：

1. 打包源码，排除构建产物、依赖目录、日志、运行状态、UI 报告、数据库和 `.env`。
2. 上传源码到 `${SRC_DIR}`，在新服务器编译 release 二进制。
3. 创建 `${APP_DIR}`，安装服务二进制、管理员密码工具和 `static/`。
4. 备份已有 release（如果存在）以及 `.env` 和 SQLite 数据库。
5. 根据 `APP_DIR` 和 `.env` 中的 `PORT` 渲染 systemd 模板；不再依赖模板内的固定服务器目录。
6. 执行 `systemctl daemon-reload`、启用服务并启动。
7. 访问服务器本机的 `/api/health`，失败则返回错误并尝试恢复二进制、静态资源和 `.env`。

记录脚本最后输出的备份目录，例如：

```text
RELEASE_BACKUP=<APP_DIR>-backups/<timestamp>
```

如果脚本生成了管理员初始密码，只会在终端打印一次；使用安全渠道交付后立即修改，禁止写进日志或聊天记录。

## 6. systemd 服务

`deploy/mjy-voice-shop-rs.service` 是模板文件，包含 `@@APP_DIR@@` 和 `@@PORT@@` 占位符。推荐始终通过发布脚本安装；手工安装时先渲染：

```bash
APP_DIR=<APP_DIR>
PORT=8787
sed -e "s|@@APP_DIR@@|${APP_DIR}|g" \
    -e "s|@@PORT@@|${PORT}|g" \
    deploy/mjy-voice-shop-rs.service \
  | sudo tee /etc/systemd/system/mjy-voice-shop-rs.service >/dev/null

sudo systemctl daemon-reload
sudo systemctl enable --now mjy-voice-shop-rs.service
```

运维命令：

```bash
sudo systemctl is-active mjy-voice-shop-rs.service
sudo systemctl status mjy-voice-shop-rs.service --no-pager --full
sudo systemctl restart mjy-voice-shop-rs.service
sudo journalctl -u mjy-voice-shop-rs.service -n 100 --no-pager
sudo journalctl -u mjy-voice-shop-rs.service -f
```

修改 `${APP_DIR}/.env` 后必须重启服务。应用端口不应直接暴露到公网，优先只监听本机或由防火墙限制来源。

## 7. Nginx 与 HTTPS

### 7.1 反向代理

`deploy/mjy-voice-shop-nginx.locations.conf` 提供 location 示例。复制到自己的 HTTPS `server {}` 后，将其中的路径前缀替换成 `<BASE_PATH>`；如果不需要兼容旧路径，只保留一个主路径即可。

反代至少需要保留：

- `proxy_http_version 1.1`；
- `Upgrade` 和 `Connection` 请求头；
- `proxy_buffering off`，避免流式 TTS 被缓存；
- 足够长的 `proxy_read_timeout`/`proxy_send_timeout`；
- 与应用实际监听地址一致的 `proxy_pass`。

检查和加载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 7.2 TLS

使用自己的域名和证书。以 Certbot 为例：

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d <DOMAIN>
```

证书签发、续期、防火墙和 DNS 属于服务器基础设施工作，不由 Rust 发布脚本自动处理。设备端必须使用 HTTPS/WSS 访问公网服务。

## 8. 发布后验收

### 8.1 服务器本机

```bash
ssh <SSH_TARGET> 'systemctl is-active mjy-voice-shop-rs.service'
ssh <SSH_TARGET> 'curl -fsS http://127.0.0.1:8787/api/health'
ssh <SSH_TARGET> 'curl -fsS http://127.0.0.1:8787/api/device/config'
```

健康接口预期返回：

```json
{"status":"ok","service":"mjy-voice-shop-rs"}
```

### 8.2 公网

```bash
curl -fsS <PUBLIC_BASE_URL>/api/health
curl -fsS <PUBLIC_BASE_URL>/api/device/config

cd <CHECKOUT_DIR>/mjy-voice-shop-rs
BASE_URL=<PUBLIC_BASE_URL> npm run cloud:smoke
```

公网 smoke 会检查健康接口、匿名管理接口拒绝、演示设备凭据拒绝、默认音频档位和 Chat WebSocket 语音链路。失败时先看 Nginx error log 和 systemd journal，再区分路由、服务、凭据或外部 provider 问题。

### 8.3 设备链路

1. `GET /api/device/config`，读取当前输入/输出 profile。
2. 使用已授权的一机一密调用 `POST /api/device/auth`。
3. 按返回的四个音频参数建立 `/api/device/voice` WebSocket。
4. 发送 `audio_stream_start/chunk/end`，确认收到 `tts_audio_chunk` 和 `voice_done`。
5. 验证按键打断、下一轮语音和订单事件没有串轮。

公网验收不得使用示例设备 ID、示例设备密钥或预签 token。

## 9. 回滚

### 9.1 自动回滚范围

发布失败时，脚本会尝试恢复备份目录中的：

- 服务二进制；
- 管理员密码工具；
- `static/`；
- `.env`。

SQLite 只会备份并执行 `PRAGMA quick_check`，不会自动覆盖当前数据库。数据库回退必须由负责人确认，避免丢失新版本写入的数据。

### 9.2 手工回滚

将 `<BACKUP_DIR>` 和 `<APP_DIR>` 替换为本次发布实际值：

```bash
BACKUP_DIR=<BACKUP_DIR>
APP_DIR=<APP_DIR>

ssh <SSH_TARGET> "sudo systemctl stop mjy-voice-shop-rs.service && \
  sudo install -m 0755 '${BACKUP_DIR}/mjy-voice-shop-rs' '${APP_DIR}/mjy-voice-shop-rs' && \
  sudo install -m 0755 '${BACKUP_DIR}/mjy-admin-password' '${APP_DIR}/mjy-admin-password' && \
  sudo rm -rf '${APP_DIR}/static' && sudo cp -a '${BACKUP_DIR}/static' '${APP_DIR}/static' && \
  sudo install -m 0600 '${BACKUP_DIR}/.env' '${APP_DIR}/.env' && \
  sudo systemctl start mjy-voice-shop-rs.service"
```

回滚后重新执行第 8 节验收。数据库恢复前先停止服务，并另存当前数据库副本；确认备份文件和目标路径后再执行覆盖。

## 10. 管理员凭据轮换

日常发布：

```bash
ROTATE_ADMIN_CREDENTIALS=0 bash scripts/deploy-jd.sh
```

明确需要轮换时：

```bash
ROTATE_ADMIN_CREDENTIALS=1 bash scripts/deploy-jd.sh
```

脚本会备份旧 `.env`，生成新的随机管理员初始密码并只在终端打印一次。轮换后检查管理员登录、设备授权页面和服务日志。

## 11. 常见故障

| 现象 | 检查方向 |
| --- | --- |
| SSH 失败 | `<SSH_TARGET>`、公钥权限、远端网络和 sudo 权限 |
| Cargo 下载失败 | Rust/Cargo 镜像、DNS、代理和磁盘空间 |
| systemd 启动失败 | `.env`、数据库路径、端口占用、二进制权限；查看 `journalctl` |
| Nginx 502 | `proxy_pass`、应用监听端口、防火墙和服务状态 |
| 页面能开但 WebSocket 失败 | `Upgrade/Connection`、HTTPS/WSS、超时和 `<BASE_PATH>` |
| 公网 smoke 失败 | 先分别验证 health、device config、匿名管理门禁，再看 provider |
| 设备鉴权失败 | 一机一密是否已创建/启用、服务器时间是否正确、是否误用示例凭据 |
