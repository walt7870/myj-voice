# 登录页优化与管理员凭据轮换设计

## 目标

在不改变设备授权、对话数据和语音协议的前提下，优化单管理员登录页，并将管理员用户名改为 `myjadmin`。

## 页面设计

- 采用精致、克制的居中卡片方案，不做左右分栏或复杂动画。
- 页面使用浅蓝灰背景、弱光晕和细微网格纹理；登录卡片宽度约 440px，水平和垂直居中。
- 卡片保留现有品牌蓝色，增加层次、留白、输入框焦点和按钮交互状态。
- 桌面端和移动端都必须完整显示，不出现横向滚动或卡片超出视口。
- 不引入外部字体、图片或新前端依赖，保持页面快速加载。
- 保留现有登录、限流、错误提示和安全返回原管理 URL 逻辑。

## 管理员凭据

- 系统仍只有一个管理员，固定用户名从 `admin` 改为 `myjadmin`。
- 登录页的用户名默认值同步改为 `myjadmin`。
- 发布时在服务器上生成 24 位随机十六进制密码，只包含数字和小写字母，不含 `/`、空格或 Shell 特殊字符。
- `.env` 只保存 Argon2id 密码哈希，数据库不保存密码；明文密码仅在发布成功后交付一次。
- 凭据轮换后旧管理员会话失效；设备密钥、设备 token 和设备连接不受影响。

## 发布安全边界

- 发布前备份当前程序、静态资源和 `.env`，不覆盖或恢复数据库。
- 只替换 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD_HASH`，其他线上环境变量原样保留。
- 发布后验证服务健康、HTTPS 登录、授权列表、历史对话和公网语音链路。
- 发布前后比较设备授权摘要和业务表记录数，不得减少。

## 验收标准

- 1440×1000 和 390×844 视口中，登录卡片均居中、无溢出、关键控件可见。
- `myjadmin` 与新密码可登录，旧用户名 `admin` 不可登录。
- 密码为 24 位小写十六进制字符，明确不包含 `/`。
- 登录后授权数量和对话数量与发布前一致。
- 已有设备授权哈希摘要不变，公网设备配置和语音链路仍可用。
