# 单管理员设备授权管理 MVP 设计

日期：2026-07-28

## 背景

当前生产服务的设备已经通过 `POST /api/device/auth` 获取设备令牌，并通过 `WS /api/device/voice` 使用语音服务。管理页面目前只允许服务器本机或 SSH 隧道访问，公网无法登录管理。

本阶段优先保证既有设备持续可用，快速提供一个可公网登录的单管理员后台。此前设计的多授权账号、账号绑定设备、设备范围对话隔离和八小时 HMAC 签名会话均保留为后续能力，不在本 MVP 实现。

## 目标

- 提供固定用户名 `admin` 的独立后台登录页。
- 管理员密码使用 `.env` 中的 Argon2id 哈希，不保存明文。
- 使用服务端随机 Session 和浏览器会话 Cookie，不设置八小时固定期限。
- 保留服务器本机和 SSH 隧道免登录管理。
- `admin` 可查看全部对话，包括旧的无 `device_id` 对话。
- `admin` 可查看、新建、启停和重置设备授权。
- 现有设备授权发布后保持原状态、原密钥和原协议。
- 不清空、不重建、不猜测迁移现有 SQLite 数据。

## 非目标与保留项

- 不创建普通后台账号。
- 不实现账号与设备绑定。
- 不实现每个授权账号独立查看对话。
- 不实现八小时会话过期。
- 不实现 Cookie 负载 HMAC 签名。
- 不提供设备授权删除。
- 不在页面重新展示既有设备的原始密钥。

## 管理员配置

服务读取以下环境变量：

- `ADMIN_USERNAME`：本阶段固定为 `admin`。
- `ADMIN_PASSWORD_HASH`：Argon2id 密码哈希。

生产环境公开绑定时，缺少管理员用户名或密码哈希必须拒绝启动。维护命令从标准输入读取初始密码，生成 Argon2id 哈希；发布流程只在缺少配置时创建随机密码并显示一次，不把明文写入命令参数、数据库或日志。

修改密码哈希并重启服务时，旧 Session 全部失效。

## 服务端 Session

新增 `admin_sessions` 表：

- `session_hash`：随机 Session ID 的 SHA-256 哈希，主键。
- `config_fingerprint`：当前管理员用户名和密码哈希的不可逆指纹。
- `created_at`。
- `revoked_at`：主动退出或服务端撤销时间。

登录成功后使用操作系统安全随机源生成 32 字节 Session ID。数据库只保存哈希，浏览器 Cookie 保存原始随机值。Cookie 属性为 `HttpOnly`、`Secure`、`SameSite=Strict`、`Path=/`，不设置 `Max-Age` 或 `Expires`，因此属于浏览器会话 Cookie。

每次后台请求重新查询 Session，并比较 `config_fingerprint`。管理员修改密码哈希后，已有 Session 无需逐条迁移即可失效。退出登录将当前 Session 标记为撤销并清除 Cookie。

## 现有本机访问

保留当前严格来源判断：TCP peer 必须是 loopback，存在 `X-Real-IP` 时也必须是 loopback。本机或 SSH 隧道访问继续免登录并拥有管理员等价权限。公网请求不能通过伪造转发头触发该绕过。

## 设备授权管理

授权管理直接使用现有 `devices` 表，不增加账号归属迁移。所有现有和新增设备授权均由唯一的 `admin` 管理。

管理接口提供：

- `GET /api/admin/device-authorizations`：列出设备 ID、名称、启用状态和最近对话时间。
- `POST /api/admin/device-authorizations`：创建新设备，生成随机设备密钥，数据库只保存现有格式的哈希，明文只在成功响应中显示一次。
- `PUT /api/admin/device-authorizations/{device_id}`：修改名称或启用状态。
- `POST /api/admin/device-authorizations/{device_id}/reset-secret`：二次确认后生成新密钥，明文只显示一次。

不提供删除接口。新建设备 ID 必须唯一；冲突返回 `409 device_already_exists`。重置或停用只影响管理员明确操作的目标设备。

## 设备端兼容边界

以下现有行为完全保持：

- `/api/device/auth` 的请求和响应结构。
- `issue_device_token`、`verify_device_token` 和 `server_secret`。
- 设备令牌有效期。
- `/api/device/config` 和 `/api/device/voice` 协议。
- 已有 `devices.secret_hash` 的验证方式。

发布和管理员登录不得自动修改任何现有 `devices` 行。设备密钥只有管理员主动重置时变化，设备只有管理员主动停用时被拒绝。

## 对话权限

唯一管理员可读取全部对话：

- 旧的 `device_id = NULL` 对话。
- 浏览器体验页产生的无归属对话。
- 所有设备归属对话。

已实现的设备对话归属写入继续保留，用于展示设备来源并为未来多账号隔离打基础，但本 MVP 不按设备过滤管理员查询。

## 页面

### 登录页

- 用户名和密码输入。
- 登录成功返回原始管理 URL。
- 错误统一显示“账号或密码错误”。
- 不使用 `localStorage` 或 `sessionStorage` 保存密码或 Session。

### 授权管理页

- 展示现有设备授权列表。
- 新建授权并一次性展示设备密钥。
- 启用、停用和修改名称。
- 重置密钥前二次确认，成功后一次性展示新密钥。
- 关闭一次性密钥区域后从 DOM 清除明文。

所有管理页面提供退出登录入口。

## 安全与错误处理

- 密码使用 Argon2id 验证。
- 登录错误不区分用户名不存在和密码错误。
- 同一来源在十分钟内最多失败五次，超限返回 `429 login_rate_limited`。
- 公网状态变更请求只接受 JSON，并校验 `Origin` 与请求主机一致。
- 未登录管理 API 返回 `401 login_required`。
- 未登录管理 HTML 跳转登录页。
- 设备授权冲突返回 `409 device_already_exists`。
- 不记录密码、设备明文密钥、Cookie 或完整登录请求体。

## 测试与验收

### 后端

- 正确/错误登录、统一错误和限速。
- Session 创建、退出、撤销、伪造随机值和修改密码哈希后的失效。
- 本机/SSH 绕过继续有效，公网伪造头继续失败。
- 管理员能读取全部旧对话和设备对话。
- 设备授权列表、新建、启停、重命名、重置和冲突。
- 新建和重置响应只显示一次设备密钥，数据库和日志不含明文。

### 设备兼容回归

- 发布前已有设备仍可调用 `/api/device/auth`。
- 已签发且未过期的设备令牌仍可升级 `/api/device/voice`。
- 设备配置和语音协议契约测试保持通过。
- 普通后台登录、退出和服务重启不修改设备记录。
- 只有显式停用或重置目标设备才改变其授权行为。

### 前端与发布

- 登录页和授权管理页通过桌面及手机宽度验收。
- 发布前备份 SQLite、二进制、静态资源和 `.env`。
- 发布前后比较设备、对话、消息、事件和订单记录数，不允许减少。
- 验证健康检查、体验页、设备认证、设备配置和设备语音不受影响。

## 回滚

代码、静态资源和 `.env` 可从发布前备份恢复。数据库只新增 `admin_sessions` 表并沿用已增加的 `conversations.device_id` 字段；旧版本会忽略这些结构，不需要删除表或字段。回滚不得恢复或覆盖现有设备密钥，除非管理员明确要求回退某次主动重置。
