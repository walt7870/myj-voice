# 管理后台概览业务数据设计

## 背景与目标

后台菜单合并后，概览页仍只显示模型、声音、商品数量、订单数量和设备音频五项摘要。订单加载只更新数量，对话加载在概览页找不到完整列表容器时会直接返回，因此管理人员无法在概览页看到最近订单和最近对话。

本次保持现有五项菜单，不恢复历史页面，在概览页增加最近订单与最近对话两个数据区。每个数据区最多展示五条记录，并保留进入完整管理页的入口。

## 页面结构

五项摘要卡片和核心链路保持不变。在摘要卡片下方增加“业务动态”区域，由两个并列的独立面板组成：

- 最近订单：展示订单短编号、状态、触发时间、商品项数和金额，右上角链接到 `admin-commerce.html#orders`。
- 最近对话：展示会话短编号、最后一条用户输入、触发时间和消息数，右上角链接到 `admin-conversations.html`。

桌面端两列排列，窄屏改为单列。列表采用紧凑行布局，不嵌套额外卡片，也不在概览页提供编辑、退款等操作。

## 数据流

继续复用现有请求，不新增后端接口：

- `POST /api/orders/list` 返回订单列表；`loadAdminOrders` 同时更新订单数量与最近订单区域。
- `GET /api/admin/conversations?page=1&page_size=5` 返回最近对话；`loadConversations` 在概览页存在最近对话容器时也执行请求，但只有完整会话页才加载首条详情和分页交互。

订单与对话渲染继续使用现有字段兼容函数、时间格式化与 HTML 转义方法，避免形成第二套数据契约。

## 状态与错误处理

两个区域均明确区分四种状态：

- 加载中：页面初始显示“正在加载”。
- 有数据：最多显示五条最近记录。
- 空数据：分别显示“暂无订单”和“暂无对话”。
- 加载失败或无内部权限：在对应区域显示失败或仅限本机管理提示，不让旧的加载文案长期停留。

单个接口失败只影响对应区域，不遮挡另一组数据和现有摘要。

## 测试与验收

先扩展现有 UI 验收脚本，使其在当前实现上因缺少两个概览数据容器而失败，再实现页面与渲染逻辑。

验收条件：

1. 概览页包含最近订单、最近对话和两个“查看全部”入口。
2. 两个区域在本机访问时最终处于有数据或空数据状态，不停留在加载中。
3. 每个区域最多显示五条，文本经过转义，长编号和长输入不会撑破布局。
4. 公网受限访问显示仅限本机提示，不暴露管理数据。
5. 桌面、平板和移动端无横向溢出；完整订单页与会话页行为保持不变。

## 非目标

- 不恢复已删除的历史后台页面。
- 不新增或修改订单、对话接口。
- 不在概览页增加详情、退款、删除或编辑操作。
- 不改变后台仅限服务器本机或 SSH 隧道管理的安全边界。
