# 管理后台菜单合并设计

日期：2026-07-29

## 背景与目标

管理后台目前有 10 个同级菜单，配置、业务与接入页面混排，用户需要逐项判断功能归属。每个独立 HTML 页面还重复维护同一份侧边菜单，增加了信息噪声和维护成本。

本次将菜单收敛为 5 个稳定的一级入口，并把同一业务域内的页面合并为页内标签。旧页面地址不保留兼容跳转，也不再纳入验收范围。

## 最终信息架构

1. `概览`
   - 保留服务指标和核心链路总览。
2. `语音配置`
   - `能力授权`
   - `声音与模型`
   - `角色与分析`
3. `商品与订单`
   - `商品库`
   - `订单列表`
   - `订单接入`
4. `会话记录`
   - 保留现有历史对话列表与详情能力，仅统一菜单命名。
5. `接入管理`
   - `设备接入`
   - `小程序 C 端`

概览与会话记录职责单一，继续作为独立页面。其余 8 个原页面合并为 3 个业务域页面。

## 页面与文件结构

- `static/admin.html`：概览。
- `static/admin-voice.html`：改造成语音配置聚合页。
- `static/admin-commerce.html`：新增商品与订单聚合页。
- `static/admin-conversations.html`：会话记录。
- `static/admin-integrations.html`：新增接入管理聚合页。

以下旧页面从产品界面和验收范围移除，并删除对应静态文件：

- `static/admin-capability.html`
- `static/admin-prompts.html`
- `static/admin-products.html`
- `static/admin-orders.html`
- `static/admin-order-mcp.html`
- `static/admin-devices.html`
- `static/admin-miniprogram-c.html`

所有保留页面使用相同的 5 项侧边菜单，概览卡片链接同步指向新的聚合页及对应标签。

## 标签交互

聚合页使用统一的标签组件：

- 标签按钮通过 `data-admin-tab` 声明目标面板。
- 面板通过 `data-admin-panel` 与标签一一对应。
- 当前标签写入 URL hash，例如 `admin-voice.html#model`。
- 初次加载时优先读取合法 hash；hash 缺失或非法时打开第一个标签。
- 点击标签、浏览器前进或后退、刷新页面时，选中状态和可见面板保持一致。
- 标签具备 `tablist`、`tab`、`tabpanel`、`aria-selected`、`aria-controls` 和键盘方向键切换能力。
- 未激活面板使用 `hidden`，避免多个长页面同时堆叠。

标签逻辑作为通用行为放入 `static/admin.js`，不为每个聚合页复制实现。

## 页面操作与状态

### 语音配置

三组配置共享现有的配置读取和保存接口。页面顶部只保留一组保存操作与一个状态提示，避免合并后出现重复 ID。用户可以跨标签修改字段，再一次性保存。

### 商品与订单

三个标签的数据和操作保持独立：

- 商品库标签内提供新增商品及商品保存、删除操作。
- 订单列表标签内提供刷新订单、选择订单和查看详情。
- 订单接入标签内提供 MCP 开关、上下文、能力映射和保存操作。

新增商品、刷新订单、保存订单接入分别放在对应标签内部，不把不同任务的按钮混在页面顶栏。页面使用一个共享状态区域承接现有 `adminStatus` 文案，订单加载状态继续使用 `orderAdminStatus`。

### 接入管理

设备协议说明与小程序接口调试各自保留完整内容，在两个互斥标签中展示。加载和调试失败继续显示在各自现有状态区域。

## 数据流与权限边界

业务接口和服务端路由不变。本次只调整静态页面结构、客户端导航与验收脚本。

`static/admin.js` 继续按 DOM 元素是否存在决定加载哪些数据。聚合页会加载其业务域内所需数据；不存在于当前页面的初始化函数仍立即返回。现有内部访问权限检测和 HTTP 403 降级保持不变：页面标记受限状态、显示提示，并禁用主内容区域内的可编辑控件。

## 响应式与视觉规则

- 桌面端保持左侧菜单和右侧内容布局。
- 平板与手机沿用现有响应式菜单规则，标签行允许横向滚动或自然换行，不挤压正文。
- 选中菜单与选中标签必须有明确、互不混淆的视觉层级。
- 长表单、订单详情和小程序调试内容只在对应标签激活时显示。
- 不在本次改造中重做配色、卡片样式或业务表单布局。

## 错误处理

- 非法 URL hash 回退到首个标签，不报错。
- 目标面板缺失时忽略该标签并回退到首个有效标签。
- 接口失败继续走现有 `runAdminTask` 和页面状态提示。
- 权限不足继续执行现有 403 降级，不因标签隐藏而遗漏禁用控件。

## 验收与测试

更新 `scripts/ui-acceptance.mjs`，仅验收 5 个新一级页面，并为聚合页覆盖：

- 侧边菜单只有 5 个一级入口，当前入口高亮正确。
- 每个标签都能显示对应关键控件并隐藏其他面板。
- URL hash 初始化、点击切换、刷新和前进/后退行为正确。
- 非法 hash 回退到首个标签。
- 桌面、平板、手机视口无文字溢出、异常卡片宽度或标签不可达。
- 403 响应下提示可见，所有可编辑控件均被禁用，包括未激活标签内的控件。
- 概览卡片和“开始配置”链接均指向新页面。

## 非目标

- 不改变配置字段、默认值或保存语义。
- 不保留旧静态页面或旧 URL 重定向。
- 不引入前端框架或构建步骤。
- 不重构与菜单合并无关的后台业务逻辑。
